# ov-24: Concept metadata as one pill in the header, times relative

**What to build:** the trust, lifecycle and provenance metadata move out of the
body into a single segmented pill next to the Concept title in `TileHeader`
(desktop, signed-in web, and — via wr-1 — the anonymous reader). The header
stays clean: the pill says *that* there is metadata and its state; the detail
lives in a popover. Every timestamp Sunstone shows from Frontmatter is relative
("3 days ago") with the exact time on hover.

Mockup (chosen variant B, 2026-10-14): `[🛡 Reviewed | 📖 3 | 🕒 stale]` after
the title; hovering it for 0.5 s opens one popover with three sections —
Trust (tier chip, Generated by actor + time, Verified events actor + time),
Lifecycle (status, stale since …), Sources (count, "view ↓" jumps to the
Sources section).

- [x] Pill segments, each shown only when its data exists: trust tier (accent when Human-reviewed), sources count, lifecycle (`stale` in danger colour; otherwise the status if not `stable`). No metadata → no pill
- [x] The popover opens on hover after 500 ms, stays open while the pointer is over pill or popover, closes on leave and on Escape (via `useOverlay`); keyboard focus on the pill opens it too
- [x] The trust line above the body is removed in the editor, the native render (web reader, print stays as decided below) and the fake render

## Decisions

- Variant B (one segmented pill, one combined popover) over per-badge popovers
  or icon-only badges (Daniel, 2026-10-14).
- Open on hover after 0.5 s (Daniel, 2026-10-14).
- Print/PDF has no hover: the print view keeps a compact static metadata line
  (tier, generated/verified with absolute dates) under the title.
- Relative-time math stays in TS (display formatting, not a shared algorithm);
  parsing still goes through the shared ISO check (`isIsoDatetime`, ov-19).
- In the anonymous reader, the pill arrives with wr-1's `TileHeader`; if wr-1
  has not landed, this ticket waits for it rather than adding the pill to the
  old concept strip.
- Short tier words in the pill: *Reviewed* / *Confirmed* / *Unverified*; the
  popover's tier chip keeps the full names (*Human-reviewed*, …).
- A legacy `timestamp` alone has no tier, so it gets no trust segment (and no
  pill on its own); the popover lists it as *Generated (timestamp)* when other
  segments open it.
- The trust data reaches the anonymous reader on the render payload
  (`RenderPayload.trust`, `sourceCount`), since SSR has no wasm; the render HTML
  drops the trust line (native and fake alike) and `PrintView` draws the static
  line from `payload.trust` under the first `<h1>`. The native `render/trust.rs`
  markup is gone; `src/lib/trust.ts` is now the print line only.
- The render writes Frontmatter times as `<time class="fm-time" datetime>` with
  the value as written; the browser re-words them (the server knows neither
  the reader's clock nor time zone). SSR first paint therefore shows the raw
  value until hydration.
- Only `isIsoDatetime` values (explicit offset) read relative; a bare date
  (`2026-09-01`) stays as written. The epoch still comes from `parseInstant`
  until ov-19 adds a shared `epochSeconds`.
- Usage phrase: a whole calendar month reads `in September 2026` (with the
  year: the render has no "now" to drop it against), a whole year `in 2025`,
  else `since` / `until` / `from … to …` with the bounds as times. Rust
  (`usage_html`) and TS (`usagePhrase`) share the wording with matching cases,
  following the earlier `window_text` / `usageText` precedent.
