# ov-9: Trust family — `generated`, `verified`, and trust tiers

**What to build:** a reader can tell at a glance who wrote a Concept, who has confirmed it, and how recently — and an author can edit all of it as YAML. OKF v0.2 replaces the flat `timestamp` with `generated: { by, at }`, adds `verified` as a list of `{ by, at }` confirmation events, and defines three derived trust tiers: no `verified` key is unverified, `verified` by non-`human:` actors only is machine-confirmed, and any `human:` actor makes it human-reviewed. Tiers are derived, never stored.

Two consumer rules are mandatory, not stylistic. A bare `verified` mapping written without the list dash MUST be treated as a one-element list. And a Concept missing any of these keys MUST still be consumable — the absence carries meaning but is never an error.

This ticket also carries the v0.1 migration, because it owns the same field: `timestamp` is superseded by `generated.at`, and a consumer MAY fall back to a legacy `timestamp` when `generated` is absent.

- [x] `generated` and `verified` parse and render, and both are authorable in the Frontmatter editor, including adding and removing verification events
- [x] A bare `verified` mapping is normalised to a one-element list on read, and editing it does not corrupt a Concept that used the bare form
- [x] `generated.by` is required within `generated`; a `generated` block missing it degrades visibly rather than being dropped
- [x] Timestamps are ISO 8601 with an explicit UTC offset on write, and a value without one is displayed rather than rejected
- [x] The derived trust tier is surfaced to the reader and recomputed from `verified` alone, never persisted
- [x] A Concept carrying only a legacy `timestamp` displays it as the generation time, and completion offers `generated` rather than `timestamp` for new Concepts
- [x] In an OKF Bundle, lint reports a `generated` block missing `by` as an error and a non-ISO `at` as a warning; in a non-OKF Bundle it says nothing ([ov-3](ov-3-okf-language-service.md))
- [x] A Concept with none of these keys renders normally with no warning
- [x] Unit tests cover tier derivation, bare-mapping normalisation and the legacy fallback
- [x] All four gates green

## Decisions

- The reader surface is a **trust line** above the body: a block widget before the first line in the editor (hybrid and reading), prepended HTML in the native render (web viewer, print) and the fake render. It is the counterpart of ov-17's Sources section at the end, and like it is never written to the file. Order: tier chip, *Generated by* actor and date, *Verified* events (actor and date each, in list order).
- The tier chip shows only when the Concept has `generated` or `verified`. A Concept with only a legacy `timestamp` shows *Generated <date>* with no tier, because labelling every v0.1 Concept "Unverified" would be noise. `verified: []` and an empty `verified:` count as no events, so *Unverified*.
- The line is not gated on the `okf_version` marker, the same as the Sources section. Lint and completion are gated (ADR 0009). So a plain folder whose notes carry `timestamp` also shows *Generated <date>*.
- A datetime that is ISO 8601 with an offset shows as its date (`2026-06-20`) with the full value on hover. Anything else is shown verbatim.
- "On write" is read as the completion: an `at` offers the current UTC time to the second (`…Z`). Nothing rewrites existing values.
- Lint beyond the AC, all warnings: a `generated` that is not a mapping, a `verified` that is neither a list nor one mapping, list items that are not mappings, and events missing `by` or `at`. Actor shape is not linted (ov-4: never an error).
